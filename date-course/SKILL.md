# 데이트 코스 추천 (Date Course Recommender)

사용자에게 지역·시간·취향에 맞는 **실제 가게가 포함된, 동선이 현실적인 데이트 코스**를 여러 선택지로 제안한다.
모든 출력은 **한국어**로 한다. 기본 지역은 한국이다.

## 1단계 — 입력 수집

다음 3가지 정보가 필요하다. 사용자가 처음 요청에서 안 준 항목이 있으면 **AskUserQuestion으로 물어본다** (이미 준 항목은 다시 묻지 않는다).

1. **지역/장소** — 예: "서울 성수동", "부산 서면", "대전 둔산동"
2. **시간대 / 소요시간** — 예: "오후 2시부터 4시간", "저녁 데이트", "점심~저녁 종일"
3. **취향 / 분위기** — 예: "감성적인 카페", "활동적인/액티비티", "조용한", "맛집 위주", "실내 위주(비 옴)"

세 가지가 모두 모이기 전에는 코스를 만들지 않는다. (예산·관계 단계 등은 사용자가 먼저 말하면 반영하되, 없으면 굳이 묻지 않는다.)

## 2단계 — 실제 가게 검색 (병렬)

한 지역 안에서 서로 성격이 다른 코스를 만들려면 후보가 넉넉해야 한다. **여러 카테고리를 한 번에 병렬 `WebSearch`로** 검색한다 (한 메시지에서 여러 검색을 동시에 호출).

검색할 카테고리 예시 (분위기에 맞게 취사선택, 취향/분위기 키워드를 검색어에 반영):
- 카페 / 디저트 — 예: `성수동 감성 카페 추천 2025`
- 식당 (점심/저녁) — 예: `성수동 저녁 데이트 맛집`
- 산책 / 명소 / 포토스팟 — 예: `성수동 데이트 산책 코스`
- 액티비티 / 전시 / 실내 — 예: `성수동 전시회`, `성수동 실내 데이트`

소요시간에 맞춰 코스에 넣을 장소 개수를 정한다 (대략 2시간=2곳, 4시간=3곳, 종일=4~5곳). 코스 2~3개를 만들 것이므로 카테고리별로 후보를 2곳 이상 확보한다.

### 검색 품질 · 정확도 규칙
- 검색 결과에서 **구체적인 가게 이름**을 뽑는다. 이름을 못 찾겠으면 검색어를 바꿔 그 카테고리를 한 번 더 시도한다.
- **최신성 확인**: 최근(가급적 1~2년 내) 리뷰·언급이 있는 곳을 우선한다. "폐업", "영업종료", "이전" 신호가 보이면 제외한다.
- **위치 교차 확인**: 뽑은 가게가 실제로 그 지역/동에 있는지 확인한다. 이름이 같은 다른 지점을 잘못 넣지 않는다.
- 실제 이름을 확인하지 못한 장소는 **지어내지 말고**, 그 자리는 "○○ 인근 카페"처럼 유형으로만 두고 재확인 필요를 표시한다.

## 3단계 — 동선 설계 (코스 조립)

검색으로 확보한 후보를 **하나의 현실적인 동선**으로 엮는다. 이 단계가 코스 품질을 좌우한다.

- **근접성 우선**: 한 코스 안의 장소들은 서로 가깝게 묶는다. 도보 15분 이내를 기본으로 하고, 멀면 대중교통/차 이동 시간을 명시한다. 지역을 가로질러 왔다 갔다 하는(backtracking) 동선은 피하고 **한 방향으로 흐르게** 배치한다.
- **시간 논리**: 식사는 식사 시간대(점심 12~13시, 저녁 18~19시)에, 카페·디저트는 식후에, 산책·포토스팟은 낮이나 노을 시간에 배치한다.
- **이동 명시**: 장소 사이마다 이동 수단과 대략 소요시간을 넣는다 (예: 도보 8분 / 지하철 2정거장 6분 / 택시 10분).
- **머무는 시간**: 각 장소의 예상 체류시간을 넣고, 이동시간까지 더해 전체가 사용자의 소요시간에 맞는지 확인한다.

## 4단계 — 코스 선택지 구성 (출력)

**서로 성격이 다른 코스 2~3개**를 만든다. 각 코스는 다음 형식으로:

```
### A안 · <컨셉 한 줄> (예: 감성 카페 데이트)
🗺️ 동선: <출발지> → <2번째> → <3번째>  (총 이동 도보 20분 내외)
💰 예상 비용: 1인 약 3~4만 원

- ⏰ 14:00  <실제 가게 이름> — <추천 이유 한 줄> (체류 약 1시간)
- 🚶 이동 · 도보 8분
- ⏰ 15:10  <실제 가게 이름> — <추천 이유> (체류 약 1시간 30분)
- 🚇 이동 · 지하철 2정거장 6분
- ⏰ 16:50  <실제 가게 이름> — <추천 이유> (체류 약 1시간)
```

- 코스마다 컨셉을 다르게 한다 (예: A안=감성/여유, B안=활동적, C안=맛집 투어).
- 각 코스 머리에 **🗺️ 동선 요약 한 줄**과 **💰 1인 예상 비용대**를 붙인다 (가격 정보를 못 찾으면 "가격 확인 필요"로 표기).
- 시작 시각은 사용자가 준 시간대에 맞추고, 각 장소마다 **왜 추천하는지** 한 줄과 **체류시간**을 붙인다.

## 5단계 — 마무리 안내

- **☔ Plan B 한 줄**: 실외 위주 코스라면 비/더위/추위 대비 실내 대체 장소를 한 곳 제안한다.
- **예약·확인 팁**: 예약이 필요할 법한 곳(인기 맛집·전시 등)은 미리 예약을 권한다.
- 필수 안내 한 줄: **"영업시간·휴무·예약은 방문 전에 꼭 재확인하세요 (웹 정보라 바뀌었을 수 있어요)."**
- 가능하면 각 가게의 출처 링크나 검색 근거를 함께 제공한다.
- 마지막에 "특정 코스를 더 자세히 짜줄까요? 아니면 조건을 바꿔볼까요?"처럼 다음 행동을 제안한다.

## 원칙
- 실제로 검색으로 확인한 가게만 이름을 쓴다. 없는 가게를 지어내지 않는다.
- 한 코스 안의 장소는 서로 가깝고 동선이 한 방향으로 흐르게 한다.
- 사용자가 준 분위기/취향을 반드시 코스에 반영한다.
- 출력은 간결하고 스캔하기 쉽게 (표·리스트 활용).
